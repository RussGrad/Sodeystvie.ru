# После заморозки ТЗ: репозиторий, стек, прототипы

Этот документ описывает **отдельный этап** после утверждения документов в `docs/`. Код и инфраструктура не являются частью текущей версии ТЗ, пока заказчик явно не инициирует разработку.

## 1. Репозиторий и процесс

- [ ] Инициализировать git-репозиторий в корне проекта (или подключить удалённый).
- [ ] Согласовать ветвление: `main` / `develop`, правила merge.
- [ ] При необходимости — CI (линт, сборка, деплой).

## 2. Выбор стека (из закрытых вопросов)

- **Бэкенд:** PHP **8.3** — [04-functional-spec.md](04-functional-spec.md) §0.
- **Фронтенд:** **HTML, SCSS, чистый JavaScript**, вёрстка по **БЭМ** — зафиксировано в [04-functional-spec.md](04-functional-spec.md) §0.
- Структура кода и инфраструктуры: [11-architecture.md](11-architecture.md). Дополнительно при необходимости зафиксировать в README проекта:
  - CMS / фреймворк поверх PHP;
  - БД на площадке заказчика (или иная схема — по проекту);
  - pipeline сборки SCSS → CSS (npm, gulp и т.п.).
- **Хостинг REG.RU**, домен **an-sodeystvie.ru** — при деплое согласовать доступы к панели, DNS-записи и SSL.

## 3. Дизайн и прототипы

- [ ] Wireframes ключевых страниц (главная, **каталог**, карточка объекта — обязательны по MVP).
- [ ] UI-kit: типографика, цвета, кнопки, формы.
- [ ] Согласование с заказчиком до вёрстки.

### Порядок вёрстки главной (зафиксировано в ТЗ)

1. Шапка и подвал на главной (каркас), при необходимости — заглушка вместо секций.
2. Затем по очереди секции главной (УТП, услуги, доверие и т.д.) — см. [04-functional-spec.md](04-functional-spec.md) §1.1 и §3.

## 4. Инфраструктура

- [x] Домен **an-sodeystvie.ru** и хостинг **REG.RU** — у заказчика (см. [04-functional-spec.md](04-functional-spec.md) §0).
- [ ] При выкладке: DNS под **an-sodeystvie.ru** (и при необходимости поддомен под staging), выпуск/подключение SSL в панели REG.RU.
- [ ] Staging-окружение (поддомен вида `staging.an-sodeystvie.ru` или отдельная папка) — по необходимости и тарифу REG.RU.
- [ ] Резервное копирование по политике REG.RU.

## 5. Связь с документацией

- Любое изменение объёма после заморозки ТЗ — через обновление `docs/` и версии в [README.md](README.md).
