# Интеграции

Реализация на стороне сайта зависит от выбранного стека; **назначение каналов** зафиксировано ниже. Детали по полям и воронке — в [09-open-questions.md](09-open-questions.md) (закрытые пункты) и при настройке портала Bitrix24.

## CRM и заявки (лиды)

| Канал | Назначение | Статус |
|-------|------------|--------|
| **Bitrix24** | Основной канал: создание **лида** (или иной сущности по настройке портала) из форм сайта — общая заявка и заявка с карточки объекта | Зафиксировано |
| Email | Дублирование копии заявки на почту менеджера | Опционально, TBD |

**Минимум для передачи в Bitrix24:** контактные поля формы, источник (страница/форма), для заявки по объекту — идентификатор или ссылка на объект.

**Техническая схема** (выбирается при разработке): входящий вебхук REST Bitrix24, готовый коннектор модуля CMS или серверный скрипт на PHP 8.3 с хранением секретов вне репозитория. Конкретный метод API (`crm.lead.add` и т.д.) и маппинг полей — на этапе реализации.

## Каталог объектов и CRM

| Направление | Описание |
|-------------|----------|
| **CRM → сайт** | **Выгрузка / синхронизация:** данные для каталога на сайте формируются из сущностей **Bitrix24** (конкретный тип — смарт-процесс, сделка, каталог и т.д. — задаётся при проектировании). |

- Редактирование карточки объекта для публичного каталога выполняется **в CRM**; сайт отображает результат последней успешной синхронизации.
- Реализация на PHP 8.3: исходящие запросы к REST Bitrix24 по расписанию (cron) или очередь; либо готовый модуль обмена — в зависимости от CMS.
- Маппинг полей CRM → поля каталога на сайте, фильтры и признак «показывать на сайте» — документируются при внедрении.
