## 0. Технологические решения (зафиксировано)

| Компонент | Решение |
|-----------|---------|
| Бэкенд | **PHP 8.3** — целевая версия интерпретатора на серверах разработки, staging и production. |
| Фронтенд | **HTML + SCSS + чистый JavaScript** (без обязательного React/Vue и т.п.). Стили и разметка — по методологии **БЭМ** (именование классов, структура компонентов). Сборка SCSS в CSS — инструмент на усмотрение проекта (CLI, npm-скрипт). |
| Провайдер хостинга | **REG.RU** — хостинг заказчика. |
| Домен продакшена | **an-sodeystvie.ru** (DNS и SSL — в зоне ответственности заказчика/провайдера; настройка под выкладку — по согласованию). |
| Хостинг (общее) | Развёртывание продакшена и при необходимости staging — на площадке REG.RU. Доступы (FTP/SSH, панель ispmanager и т.п.) — по передаче проекта. |
| Лиды (CRM) | **Bitrix24** — основной канал приёма заявок с сайта (создание лида/сделки; способ интеграции — см. [07-integrations.md](07-integrations.md)). |
| Каталог объектов (данные) | **Выгрузка / синхронизация из CRM** — учётные объекты ведутся в CRM; на сайт попадают через согласованный механизм (REST, cron, обмен) — см. §7.4 и [07-integrations.md](07-integrations.md). |
| Языки | **Только русский (RU)** на первом этапе (MVP): интерфейс, контент, формы. Дополнительные языки — отдельная фаза при необходимости. |
| Тема оформления | **Светлая и тёмная** — обе обязательны. Переключатель в интерфейсе (шапка или иное согласованное место); стартовая тема по `prefers-color-scheme` у пользователя; выбор сохраняется (например, `localStorage`). Все ключевые экраны MVP корректны в обеих темах. |
| Фон **тёмной** темы | Референс цвета и настроения — фотография офисной стены с логотипом: [`assets/brand/references/dark-theme-bg-reference.jpg`](../assets/brand/references/dark-theme-bg-reference.jpg). Базовый фон интерфейса — **холодный тёмный сине-серый / угольно-синий** (не чистый `#000`). Стартовый токен для вёрстки: ориентир **#1e2630** или ближайший оттенок в диапазоне **#1a202c–#232b35**, уточнить пипеткой по референсу при финальном UI-kit. Детали — [05-non-functional.md](05-non-functional.md). |

Серверная часть: фреймворк или CMS поверх PHP (Битрикс, Laravel, Symfony и т.д.) — уточняется отдельно; ограничение по рантайму сохраняется. Фронтенд-стек **зафиксирован** в таблице выше.

## 1. Объём поставки (фазы)

| Фаза | Содержание | Статус |
|------|------------|--------|
| **Фаза 1 (MVP)** | Публичный сайт: главная, **каталог объектов** (список, фильтры, карточка, заявка по объекту), услуги, о компании, контакты, юридические страницы, формы заявок; адаптивная вёрстка; базовое SEO. | Базовый объём |
| **Фаза 2** | Личный кабинет, избранное, интеграции с внешними фидами, мультиязычность — только после отдельного согласования. | Вне текущего MVP |

**Каталог объектов** входит в MVP **обязательно** (не опция).

### 1.1 Порядок реализации главной страницы (согласовано)

Работы ведутся **поэтапно**, с приёмкой промежуточного результата:

| Шаг | Что делаем | Примечание |
|-----|------------|------------|
| **1** | **Главная страница:** глобальная **шапка** и **подвал** | Единый каркас для всего сайта; меню, логотип, телефон, CTA в шапке; подвал — меню, контакты, реквизиты, ссылки на политику. Контентная область между шапкой и подвалом на этом шаге может быть минимальной (заглушка или пустой блок). |
| **2** | **Секции** главной | По очереди: первый экран (УТП), блок услуг, блок доверия и остальные согласованные секции — см. §3. |

**Каталог объектов** обязателен в MVP; очередность его реализации относительно секций главной и страниц «Услуги / О компании / Контакты» — по плану спринта, без ослабления требований к функционалу каталога.

Остальные информационные страницы — после согласования каркаса главной, если иное не решено отдельно.

## 2. Карта страниц (MVP)

| URL (пример) | Страница | Назначение |
|--------------|----------|------------|
| `/` | Главная | УТП, услуги кратко, CTA, доверие; ссылка на каталог |
| `/catalog/` *(пример)* | Каталог объектов | Список, фильтры, сортировка |
| `/catalog/{slug}/` *(пример)* | Карточка объекта | Галерея, характеристики, заявка |
| `/services/` или `/uslugi/` | Услуги (листинг + детальные при необходимости) | Описание услуг агентства |

| `/contacts/` | Контакты | Адрес, карта, форма, реквизиты |
| `/privacy/` | Политика конфиденциальности | ПДн |
| `/cookies/` или блок в политике | Cookies / согласие | По требованию юриста |
| *TBD* | Согласие на обработку ПДн | Если выносится отдельно |

ЧПУ и точные slug — согласовать с заказчиком; единый стиль (латиница или транслит).

## 3. Главная страница

### 3.1 Шапка и подвал (шаг 1 из §1.1)

- **Шапка:** **логотип компании**, **переключатель светлой/тёмной темы** (если не вынесен в другое видимое место), основное меню (**включая переход в каталог объектов**), телефон (кликабельный), CTA «Оставить заявку» или аналог.
- **Подвал:** при необходимости — **уменьшенный вариант логотипа** или текстовое наименование; меню, контакты, реквизиты, ссылки на политику, соцсети при наличии.

#### Логотип компании

- В шапке на всех страницах — **обязательный** элемент брендинга.
- Логотип ведёт на **главную страницу** (`/`).
- **Утверждённый макет (горизонтальный):** монограмма **«АН»** в виде стилизованных высотных блоков + текст **«АГЕНТСТВО НЕДВИЖИМОСТИ»** заглавными буквами; цвет — **золотой металлический градиент**; фон файла — **прозрачный**. Раскладка: горизонтальная, премиальный корпоративный стиль.
- **Основной файл для вёрстки (вектор):** [`assets/brand/logo-text.svg`](../assets/brand/logo-text.svg) — приоритет при подключении в шапке/подвале (чёткость на retina, масштабирование).
- **Запасной растр:** [`assets/brand/logo-agenciya-nedvizhimosti.png`](../assets/brand/logo-agenciya-nedvizhimosti.png) — например для писем, превью или fallback, если SVG недоступен в каком-либо контексте.
- **Две темы:** если на светлом или тёмном фоне один SVG визуально «теряется», добавить второй SVG под вторую тему в `assets/brand/` и описать переключение здесь; до этого вёрстка использует `logo-text.svg` в обеих темах с согласованными фонами шапки.
- Для `alt` подойдёт, например: «Агентство недвижимости» или полное наименование по УЧР.
- Палитры шапки/подвала задаются **отдельно для светлой и тёмной темы** (см. §0 и [05-non-functional.md](05-non-functional.md)); золотой знак должен оставаться читаемым в обоих режимах.
- Отдельный вариант **favicon** — по согласованию (упрощённая монограмма или знак из логотипа).

Шапка и подвал повторяются на внутренних страницах того же шаблона (когда они будут подключены).

### 3.2 Секции контента (шаг 2 из §1.1)

- **Первый экран:** заголовок (УТП), подзаголовок, основная кнопка действия.
- **Блок услуг:** карточки с переходом в раздел услуг или якоря.
- **Блок доверия:** цифры, партнёры, лицензии — **контент от заказчика**.

Дополнительные секции — по согласованию при наполнении.

## 4. Услуги

- Список услуг (минимум: продажа, покупка, аренда — **уточнить состав**).
- Для каждой услуги: описание, выгоды, CTA (форма или переход в контакты).
- При необходимости — отдельные подстраницы на услугу с тем же шаблоном.

## 5. О компании

- Текст о компании, фото (опционально), команда (опционально).
- Реквизиты могут дублироваться с контактами или ссылаться.

## 7. Каталог объектов *(обязательно в MVP)*

### 7.1. Список

- Пагинация или подгрузка — **уточнить** (зависит от объёма данных).
- Сортировка: по дате, по цене (возрастание/убывание) — минимум одна осмысленная сортировка.

### 7.2. Фильтры (минимальный набор)

- Тип сделки: продажа / аренда.
- Тип объекта: квартира, дом, коммерция и т.д. — **список от заказчика**.
- Цена: от–до.
- Район / метро — если есть в данных.

### 7.3. Карточка объекта

- Галерея изображений; опционально планировка.
- Цена, площадь, этаж/этажность, адрес или район (политика отображения адреса — **уточнить**).
- Описание, характеристики в таблице или списком.
- CTA: заявка на просмотр / звонок; в заявке передаётся идентификатор объекта.

### 7.4. Источник данных и управление объектами

- **Источник правды — CRM:** объекты заводятся и актуализируются в **CRM** (в связке с проектом — **Bitrix24**). Ручное наполнение каталога только в CMS **не** является основным сценарием.
- **На сайт** данные попадают через **выгрузку / синхронизацию из CRM** (периодический импорт по расписанию или по событию — уточняется при проектировании интеграции).
- Состав полей, сущность в Bitrix24 (смарт-процесс, сделка, товарный каталог и т.д.) и правила «публиковать на сайте» — **согласовать** на этапе интеграции; см. [07-integrations.md](07-integrations.md).
- При ошибке синхронизации сайт не должен «падать»; актуальность данных на стороне сайта — в пределах последней успешной выгрузки.

## 8. Формы и заявки

### 8.1. Общая заявка

| Поле | Обязательность |
|------|----------------|
| Имя | Да |
| Телефон | Да |
| Email | По решению заказчика |
| Комментарий | Нет |
| Согласие на обработку ПДн | Да (чекбокс или явная ссылка на политику) |

### 8.2. Заявка с карточки объекта

- Те же поля + скрытое/системное поле: ID или URL объекта.

### 8.3. Поведение после отправки

- Сообщение об успехе на странице или модальное окно.
- Данные заявки передаются в **Bitrix24** (лид или согласованная сущность) — см. [07-integrations.md](07-integrations.md). Дублирование на email — **опционально**, по согласованию.

### 8.4. Антиспам

- Требование: снижение спама без ухудшения UX; конкретная реализация — после выбора стека.

---

## 9. Навигация и общие элементы

- Меню: доступ ко всем разделам MVP.
- «Хлебные крошки» — на вложенных страницах (услуги, карточка объекта).
- Страница **404**: понятный текст, ссылки на главную и **каталог**.

---

## 10. Юридические требования (функционально)

- Размещение актуальной политики обработки ПДн.
- Формы не отправляются без принятия условий обработки данных (в объёме, который задаёт юрист).

---

## 11. Вне scope MVP

- Личный кабинет пользователя.
- Онлайн-оплата.
- Сложные калькуляторы ипотеки (можно как фаза 2).
- Автоматическая синхронизация с внешними площадками без отдельного ТЗ.
