# Нефункциональные требования (NFR)

## Производительность

- Страницы должны ощущаться быстрыми на мобильных сетях; конкретные метрики (LCP, TTFB) **уточнить на площадке заказчика** после выбора стека.
- Изображения объектов: адаптивные форматы, ленивая загрузка ниже первого экрана где уместно.

## Вёрстка и стили (зафиксировано)

- Разметка: **HTML**. Стили: **SCSS**, компиляция в CSS — в процессе сборки проекта.
- Именование классов и структура блоков — **БЭМ** ([04-functional-spec.md](04-functional-spec.md) §0). Поведение на клиенте — **чистый JavaScript** без обязательной зависимости от React/Vue/Angular.

## Светлая и тёмная тема

- Реализованы **обе** темы ([04-functional-spec.md](04-functional-spec.md) §0): отдельные наборы токенов цветов (фон, текст, границы, кнопки, карточки каталога).
- **Тёмная тема — фон:** визуальный ориентир зафиксирован референсом [`assets/brand/references/dark-theme-bg-reference.jpg`](../assets/brand/references/dark-theme-bg-reference.jpg) (тёмная стена офиса, холодный приглушённый тон). Для CSS-переменных основного фона использовать оттенок в духе **navy / charcoal blue** (порядок величины: **#1a202c – #232b35**; итоговое значение — снять с референса при сборке палитры). Текстура стены на макете сайта **не обязательна**; важен **цвет и «холодное» настроение**.
- **Светлая тема:** палитра согласуется отдельно так, чтобы сохранялась премиальность и читаемость; контраст с золотым логотипом — как в макете.
- На корневом элементе или `body` — класс/атрибут темы; при необходимости `color-scheme` для нативных элементов форм.
- Контраст текста и интерактивных элементов — проверить в **обеих** темах (ориентир — WCAG 2.1 AA для основного текста где возможно).

## Адаптивность

- Корректное отображение и удобство на **мобильных, планшетах и десктопах** (основные брейкпоинты задаются на этапе дизайна/вёрстки).

## Доступность (базовый уровень)

- Логичный порядок фокуса с клавиатуры для форм и навигации.
- Контраст текста и фона — не ниже разумного минимума (уточнить по WCAG при дизайне).
- У информативных изображений — осмысленные `alt` (особенно в каталоге).

## Безопасность

- HTTPS на продакшене.
- Защита форм от спама: механизм **согласовать** (капча, rate limit, honeypot — в зависимости от стека).
- Данные заявок не передавать третьим лицам кроме согласованных каналов (**Bitrix24**; опционально — почта для дублирования).

- Атрибут `lang` у документа: `ru`. Дополнительные языки — только отдельной фазой по согласованию ([04-functional-spec.md](04-functional-spec.md) §0).
