# Пользовательские сценарии

Роли: см. [02-glossary.md](02-glossary.md). Ниже — сценарии для **фазы 1 (MVP)**; **каталог объектов** в MVP обязателен. Расширения (личный кабинет, избранное) — в фазу 2.

---

## Гость (неавторизованный посетитель)

### С1. Первое знакомство с агентством

1. Пользователь переходит на главную из поиска или рекламы.
2. Видит УТП, основные услуги, блок доверия (реквизиты/лицензии при наличии).
3. Переходит в «Услуги» или «О компании» за подробностями.
4. **Ожидаемый результат:** понятно, чем агентство полезно и как связаться.

### С2. Оставить заявку без привязки к объекту

1. Пользователь открывает страницу «Контакты» или использует форму в подвале/на главной.
2. Заполняет обязательные поля (минимум: имя, телефон; опционально: комментарий).
3. Отправляет форму; видит сообщение об успешной отправке (или аналог).
4. **Ожидаемый результат:** заявка создаётся в **Bitrix24** ([07-integrations.md](07-integrations.md)); пользователь не остаётся без обратной связи.

### С3. Просмотр каталога объектов

1. Пользователь открывает раздел каталога.
2. Применяет фильтры (тип сделки, тип объекта, цена, район — по [04-functional-spec.md](04-functional-spec.md)).
3. Открывает карточку объекта; листает фото, читает характеристики.
4. Нажимает «Заказать просмотр» / «Позвонить» / форму на карточке.
5. **Ожидаемый результат:** объект идентифицируется в заявке (ID или ссылка), контактные действия работают на мобильном.

### С4. Связь по телефону или мессенджеру

1. Пользователь нажимает на номер телефона (на мобильном — набор) или на иконку мессенджера.
2. **Ожидаемый результат:** целевой номер/чат соответствуют данным заказчика.

## Контент-редактор / администратор *(если предусмотрена CMS)*

### С5. Публикация или обновление текстовой страницы

1. Входит в систему управления (способ — по платформе).
2. Редактирует текст страницы «Услуги» / «О компании».
3. Публикует изменения.
4. **Ожидаемый результат:** изменения видны на сайте без поломки вёрстки.

### С6. Появление объекта в каталоге (данные из CRM)

1. Сотрудник создаёт или обновляет объект в **CRM (Bitrix24)** и отмечает его для публикации на сайте — по правилам, согласованным при внедрении.
2. Срабатывает **выгрузка / синхронизация** CRM → сайт.
3. **Ожидаемый результат:** объект отображается в списке и по прямой ссылке на сайте; при снятии с публикации в CRM — исчезает или скрывается согласно правилам.

## Исключения и ошибки

| Ситуация | Поведение |
|----------|-----------|
| Неверно заполнена форма | Показ ошибок у полей; форма не «теряет» введённые данные где возможно. |
| Серверная ошибка отправки | Сообщение пользователю; повторная отправка возможна. |
| Несуществующий URL | Страница 404 с навигацией на главную или каталог. |
